# v2.2.4

DSH Vision Router 2.2.4 is a Desktop and Session-recovery hotfix for the DSH 0.1.7 line.

## Highlights

- Fixes the official DSH `0.1.7-rc.2` Desktop startup failure where Vision Router could remain at `Loading plugins…` / `pending (waiting for service: settingsScope)`. The 0.1.7 Settings compatibility prelude now travels through DSH's structured `webserver/index-inject` boot table used by Electron/static carriers, while the served-Web `tapIndex()` path remains as a compatibility fallback and is deduplicated.
- Adds an exact `0.1.7-rc.2` Desktop Host bootstrap regression on `windows-latest`, so the Electron/Desktop injection carrier is validated directly instead of inferred from `dsh web` browser coverage.
- Fixes a Session event-feed recovery edge case where one transient activation-time SessionQuery read failure could permanently suppress future backfill attempts. Failed snapshots are now retried, concurrent reads remain coalesced, and a successful snapshot remains one-shot cached.
- Keeps the public minimum supported DSH Host at `0.1.0-rc.8`; no settings migration is required.

## Validation

- Exact DSH source: `0.1.7-rc.2` at `477b4f420553e8a52c2fbccc464d7561b239c443`.
- Exact Windows Desktop Host bootstrap passes with one Vision Router structured compatibility injection.
- Real `dsh web` + Chromium passes bundle recompose, Desktop structured bootstrap, cold Vision toggle, mixed attachment lifecycle, and Settings mount/save/reload/readback.
- Node 22/24, architecture/data-boundary/adversarial/fuzz, dependency review, and HOL plugin security gates pass.
- Session regression covers fail → retry → success → cached behavior; the full local suite passed `1488/1489` tests with one intentional skip, plus `8/8` Host image-delivery tests.

## Upgrade

Users on DSH `0.1.7-rc.2` Desktop should upgrade to 2.2.4. This release contains the Desktop boot fix that is not present in 2.2.3. No settings migration is required.
